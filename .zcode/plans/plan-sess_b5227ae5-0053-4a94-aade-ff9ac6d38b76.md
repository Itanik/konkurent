# Волна 2.1: вставка из ячейки, автосопоставление после заполнения заявки, матчинг v7

## Context

Два кейса из тестирования + качество сопоставления, разведаны по фактической таблице из `example_data/krep`:

1. **Вставка TSV из редактируемой ячейки не работает**: в волне 2 `EditableCell` перестал перехватывать Ctrl+V — многострочный/многоколоночный буфер вставляется в открытое поле одной ячейки. Также склеенная колонка «кол-во+ед» («9 шт» — ровно так в таблице пользователя: `qty='9 шт', unit=''`) не разбирается на кол-во + ед.изм.
2. **Сдвиг/раздувание после вставки заявки**: позиции заявки образуют группы сверху, непривязанные предложения остаются в зоне снизу (таблица «x2»); автосопоставление не срабатывает, потому что `unit` пуст (следствие кейса 1). Ожидание: заявка вставилась → предложения привязались к позициям, зона схлопнулась, свежесопоставленное подсвечено.
3. **Матчинг находит ~1 совпадение на поставщика**: порог 0.7 по фактическим данным проходят 3/69 предложений. Причины: пробелы в размерах («М 16х2000» vs «М16»), лишние слова («(уп.1 кг)», бренды), и ложные пары из-за игнорирования размера («Гайка М10» → «Гайка DIN934 М16»). Подобранная и проверенная на фикстуре формула v7 даёт ~38/69 корректных привязок.

## Изменения

### 1. Перехват вставки в редактируемой ячейке (`editable_cell.dart`, `selection_controller.dart`, `comparison_table.dart`)

- `SelectionController` получает метод `pasteGridFrom(CellAddress at, String text)` + ссылку на обработчик (как `boundsProvider`): ComparisonTable назначает функцию, которая применяет TSV-сетку от адреса (переиспользуется существующий `_pasteClipboard`/`_applyCell`).
- `EditableCell._onKeyEvent`: Ctrl+V / Cmd+V / Shift+Insert при наличии `\t` или `\n` в буфере → `_commit()`, затем `pasteGridFrom(address, text)`; вставка покидает поле, работает по-ячеечно. Одиночная строка без табов/переводов строк — обычная вставка в поле.

### 2. Разбор «кол-во + ед.изм» при вставке (`comparison_table.dart`)

- Хелпер `(String, String)? splitQtyUnit(String v)`: ведущее число + короткий нечисловой хвост («9 шт» → («9», «шт»), «5 м.п.» → («5», «м.п.»)).
- В `_applyCell` при записи в колонку кол-ва (панель заявки `c==1` и предложения `c==1`): если исходная строка вставки **не содержит** отдельной колонки ед.изм (это последняя колонка строки TSV) и значение парсится `splitQtyUnit` → пишем кол-во в qty, единицу — в unit той же строки.
- 2-колоночный TSV (название, «кол-во+ед») и 3-колоночный (название, кол-во, ед) оба работают; лишние колонки справа игнорируются.

### 3. Автосопоставление после вставки заявки (`comparison_table.dart`, `app_state_provider.dart`)

- В конце `_pasteClipboard`: если якорь в панели заявки (b == -1) и после применения `notifier.requestFullyFilled` → `notifier.autoLinkOffers()` (счётчик уже возвращается; снек не нужен — подсветка сама говорит о результате).
- Триггеры автолинка: после распознавания (есть), после вставки заявки (новый), кнопка «Сопоставить» (есть). Зона схлопывается автоматически (непривязанных почти не остаётся) — «x2» уходит.

### 4. Подсветка свежесопоставленных (`recently_linked_provider.dart` — новый, `offer_row.dart`)

- `recentlyLinkedProvider = NotifierProvider<Set<String>>`: `autoLinkOffers()` записывает id свежепривязанных предложений (замещает множество при каждом запуске; `reset()` чистит).
- `OfferRow`: если `offer.id` в множестве — фон ячейки «Предложено» мягкий зелёный (`primaryContainer` с прозрачностью), до следующего автолинка/новой сессии. Не персистится — чисто UI-подсказка.

### 5. Матчинг v7 (`fuzzy_match.dart`)

Проверено на фикстуре (69 предложений × 29 позиций):

- Сигналы: `0.3 × max(lev(норм), lev(компакт-без-пробелов)) + 0.5 × containment + 0.2 × jaccard` (компактный lev снимает проблему «М 16х2000» vs «М16»).
- Порог `kMatchThreshold` 0.7 → **0.55**.
- **Диаметр-гард**: извлечь явный м-диаметр (`\bм\s*(\d{1,3})\b`) у обеих строк; если есть у обоих и не совпадают → счёт × 0.55. Гайки М10/М12 уходят к «Гайка DIN 934 оц» (безразмерной), а не к М16. Пары без явного «М» у одной из сторон не штрафуются («Шайба 16 (d17)» vs «ув. М16»).
- Ожидаемый результат на фикстуре: ~38/69 автоматически, остальные — честные «аналоги по другому ГОСТ» для ручной привязки drag'ом.

### 6. Тесты

- Юнит `fuzzy_match`: пары из фикстуры — «Шпилька М 16х2000 DIN 975 кл.пр.8.8 цинк» ↔ «Шпилька резьбовая М16 кл. пр. 8.8» (≥0.55); «Гайка М 10 DIN 934…» ✗ «Гайка DIN934 М16…» (штраф, ниже порога) и ✓ «Гайка DIN 934 оц»; «Шайба плоская 16 (d17)…» без штрафа; компактный замер «М16х2000»↔«М16».
- Юнит `splitQtyUnit`: «9 шт», «5 м.п.», «10», «шт» (null-хвост).
- Integration: (а) вставка 2-колоночного TSV в первую ячейку названия из режима правки → позиции с раздельными qty/unit; (б) вставка 3-колоночного TSV; (в) сценарий кейса 2 — распознанный поставщик + вставка заявки → предложения привязаны (`linkedRequestItemId != null`), зона не раздута, подсветка есть.
