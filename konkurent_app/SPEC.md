# SPEC — KonkurentApp

Flutter Desktop приложение (Windows + Linux) для создания и редактирования
конкурентных таблиц сравнения поставщиков. Работает поверх Python-движка
распознавания (`recog.py` / `normalizer.py`) через Python-sidecar.

## Ключевые сценарии

- Создание таблицы с нуля вручную
- Автозаполнение через drag&drop PDF / xlsx / docx счетов
- Редактирование ячеек, перестановка строк предложений и блоков поставщиков
- Сохранение в xlsx, открытие ранее сохранённого файла
- Сортировка поставщиков по итоговой сумме (слева самый выгодный)

## Модель данных

```dart
class AppState {
  final String requestName;
  final List<RequestItem> requestItems;  // может быть пустым
  final List<SupplierBlock> suppliers;   // порядок = порядок колонок
}

class RequestItem {
  final String id;
  final String name;
  final String qty;
  final String unit;           // Ед.изм — источник подстановки для предложений
}

class SupplierBlock {
  final String id;                    // uuid
  final String displayName;           // заголовок блока (+ «n/z» покрытие)
  final List<String> sourceFileNames; // файлы-источники (сливаются при
                                      // нескольких счетах одного поставщика)
  final String? inn;                  // ИНН (распознан или введён; строка 2 xlsx)
  final bool withoutVat;              // счёт без НДС: суммы считаются как «без НДС»
  final bool vatMovedToNet;           // тумблер «позиции без НДС» нажат
  final SupplierMeta meta;
  final List<Offer> offers;           // порядок строк внутри зон
}

class SupplierMeta {
  final String contract;       // Договор
  final String deliveryTime;   // Сроки поставки
  final String delivery;       // Доставка
  final String paymentTerms;   // Условия оплаты
  final String comment;        // Комментарий
}

enum PriceDriver { sum, price }

class Offer {
  final String id;             // uuid
  final String itemName;       // Предложено
  final double? qty;           // Кол-во
  final String? unit;          // Ед.изм (пусто → плейсхолдер из заявки)
  final double? sumWithVat;    // Сумма, с НДС (первична при driver=sum)
  final double? sumWithoutVat; // Сумма, без НДС (первична при driver=sum, б/НДС)
  final double? priceWithVat;    // хранится только при driver=price
  final double? priceWithoutVat; // хранится только при driver=price
  final PriceDriver priceDriver; // «последняя правка выигрывает»
  final String? linkedRequestItemId; // привязка к позиции заявки (группа строк)
  // displayPrice/displaySum — вычисляются, не хранятся
}
```

**Цены и НДС.** У каждой строки один источник истины — `priceDriver`:
ввели сумму → сумма хранится, цена выводится как `сумма / кол-во`; ввели цену →
цена хранится, сумма выводится как `цена × кол-во`. Вторая сторона пары всегда
**выводится** через ставку НДС и не хранится (`displaySum`/`displayPrice`).
Ставка задаётся в глобальном конфиге (`app-config.json`, по умолчанию 22 %).

У блока поставщика две операции НДС:
- **Флажок «без НДС»** — смена базиса блока: введённые значения переезжают в
  колонки нового базиса без искажения (`vatMoveValues`), колонки старого
  скрываются. Для зарубежного счёта значения и так были «без НДС» — теперь
  это отражено и в базисе.
- **Кнопка «позиции в счёте без НДС»** (иконка рядом с флажком) — тумблер:
  первое нажатие переносит значения с НДС на «без НДС», а колонка с НДС
  пересчитывается (`= без НДС × (1 + ставка)`); повторное возвращает исходные
  значения как есть (без деления). Колонки остаются видимыми
  (`vatMoveGrossToNet` / `vatMoveNetToGross`, флаг `vatMovedToNet` на блоке).
  Для счетов, где позиции выставлены без НДС, а итог с НДС.

Пара колонок другого базиса (цена + сумма) скрыта и показывается тумблером
«Сумма без НДС» в тулбаре; вторая пара тоже редактируемая.

**Связанная сетка.** Каждая позиция заявки — **группа строк**: высота группы =
max по поставщикам числа предложений, привязанных к позиции
(`Offer.linkedRequestItemId`). Ячейки заявки объединены на высоту группы;
поставщик с одним предложением в группе растягивается на неё же (визуальные
merge). Под группами — **зона без привязки** (непривязанные предложения +
запасная строка). Drag предложения: на строку своей группы — порядок; на
строку другой группы — перепривязка; на чужую колонку — перенос между
поставщиками с сохранением/обновлением привязки. Покрытие поставщика —
«n/z» в шапке: позиция закрыта, если Σ кол-во привязанных ≥ заявленного.

**Сопоставление предложений — две стратегии.** По умолчанию **позиционное**
(`linkOffersPositionally`): k-е предложение поставщика привязывается к k-й
позиции заявки — счета обычно повторяют порядок заявки, нужна лишь правка
drag'ом; поставщики с уже имеющимися привязками не трогаются (сохраняем
ручную работу), излишки остаются в зоне. Запускается после распознавания
счёта и после вставки заявки. Вторая стратегия — **нечёткое по названиям**
(`fuzzy_match.dart`: `0.3×max(Левенштейн норм., компактный) +
0.5×контейнмент + 0.2×Jaccard`, порог 0.54, диаметр-гард ×0.55 при разных
м-диаметрах) — кнопка «Сопоставить» в тулбаре: **улучшающая правка всех
привязок** — каждое предложение всех поставщиков заново сверяется со
своей позицией; уверенное совпадение перекидывает на неё (неверно
привязанные позиционно исправляются, а позиции без совпадений остаются
пустыми — предложений может быть меньше, чем позиций). Предложение
**без** уверенного совпадения остаётся там, где стояло — «брак» не
перемещает строки и не гоняет их в зону. Перемещённые подсвечиваются
мягкой зелёной заливкой (`recentlyLinkedProvider`, не персистится).

**Единицы измерения.** Глобальный словарь `units.json` (app-support): канон
+ алиасы («тн», «теор. т» → «т»). Распознанные единицы нормализуются по
словарю при добавлении счёта; в ячейках ед.изм — автодополнение; единица
вне словаря подсвечивается цветом; пустая показывает плейсхолдер — единицу
привязанной позиции заявки; в экспорт для привязанной строки с пустой
единицей пишется единица заявки.

**Клавиатура как в Excel** (когда поле не в правке): стрелки — навигация
(Shift — протяжка диапазона), Enter — вниз, Tab — вправо через блоки,
Ctrl+A — выделить всё, Ctrl+C — копировать выделение в TSV (для Excel),
Ctrl+V — вставить TSV по ячейкам от выделения (сетка дорастает), набор
текста — начать правку, Esc — выйти из правки (выделение остаётся) или
сбросить выделение.

**Высота строк** — максимум по всем ячейкам строки (перенос по словам,
без лимита), замеряется `tableLayoutProvider`. Поле редактирования занимает
всю ячейку и переносит текст — многострочные названия правятся целиком.

**Вычисляемые значения никогда не записываются константами** — они считаются
на лету и в xlsx экспортируются формулами: `=IFERROR(сумма/кол-во,"")` при
driver=sum и `=IFERROR(цена*кол-во,"")` при driver=price; итоги — `=SUM(...)`.
Все отображаемые и распознанные числа округляются до 2 знаков
(`displaySum`/`displayPrice`/`formatEditable`, sidecar `_num_or_none`).

**Пустые строки.** `displayRows = maxRows + 1`: внизу всегда есть одна запасная
пустая строка, а все пустые ячейки (и у заявки, и у поставщиков) — обычные
редактируемые `EditableCell`. Кнопок «+» нет: ввод в пустую строку создаёт
запись, и снизу автоматически появляется новая запасная. Кнопка «×» удаляет
заполненную строку. «Хвостовые» полностью пустые строки в модели схлопываются
автоматически (`_trimTrailingOffers` / `_trimTrailingRequestItems`); пустые
строки в середине сохраняются.

**Inline-редактирование**: клик по ячейке → `TextField` на месте. Подтверждение
по Enter / Tab / потере фокуса.

**Drag блоков**: горизонтальный drag за handle в `SupplierHeader`.

**Drag строк**: вертикальный drag за handle в `OfferRow`, только внутри блока.
Сброс на **заполненную** строку переставляет (уплотняет) список; сброс на
**пустую** строку меняет их местами — предложение встаёт на место пустой, а на
его прежнем месте остаётся пробел (`moveOfferToEmpty`). Так можно расставлять
пропуски между предложениями.

## Вставка из буфера (TSV, Excel-совместимо)

Панель заявки видна всегда (даже без поставщиков) и содержит минимум одну
строку, поэтому её можно заполнить первой.

- **Ctrl+V работает и из открытой ячейки**: если в буфере есть табы или
  переводы строк, правка закрывается и TSV раскладывается по ячейкам от
  этой ячейки (как в Excel). Одиночная строка вставляется в поле как текст.
- 2-колоночная копия («Название» + «Кол-во+Ед.изм» склеено, «9 шт»)
  разбирается: кол-во и единица разводятся по своим колонкам. 3-колоночная
  («Название», «Кол-во», «Ед.изм») вставляется напрямую.
- После вставки в панель заявки, если все позиции получили название,
  кол-во и ед.изм — автоматически запускается сопоставление предложений
  (свежесопоставленные подсвечиваются мягкой заливкой).
- **Ctrl+C** копирует выделение в TSV (вычисляемые цена/сумма отдают
  посчитанное значение) — вставка в Excel работает как из Excel.

## Масштаб интерфейса

- Масштаб меняет **реальные размеры** таблицы, а не масштабирует готовую картинку:
  `TableMetrics` (`lib/ui/constants.dart`) умножает высоты строк, ширины колонок,
  отступы, размеры иконок и тап-таргетов на `scale`. Поэтому при уменьшении в
  окно влезает больше колонок и строк.
- `zoomProvider` + `tableMetricsProvider` (`lib/providers/zoom_provider.dart`):
  диапазон **50–200 %, шаг 10 %**.
- `ZoomScope` (`lib/ui/zoom_scope.dart`) масштабирует текст и иконки всего
  приложения через `MediaQuery.textScaler` и `IconTheme` (без `Transform` и
  зазоров); шапка — `AppBar.toolbarHeight`/`iconTheme` пропорционально.
- Управление: кнопки `− / % / +` в шапке, `Ctrl+=`, `Ctrl+-`, `Ctrl+0`,
  `Ctrl`+колесо (только вне поля ввода). Масштаб сохраняется в `settings.json`.
- **Автоскролл средней кнопкой** (Windows-стиль): клик средним колесом ставит
  якорь, скорость прокрутки зависит от отклонения курсора, обе оси; повторный
  клик любой кнопкой выключает. **Shift+колесо** — горизонтальная прокрутка.

## Автовысота строк

`tableLayoutProvider` (`lib/providers/table_layout_provider.dart`) считает
раскладку: группы позиций (высота = max предложений поставщиков в группе),
зона без привязки, высоты каждой физической строки — максимум по тексту её
ячеек (`TextPainter`, перенос по словам, без лимита строк), метаполя так же.
В экспортируемом xlsx высоты строк не задаются явно (перенос включён, Excel
подбирает высоту сам).

## Ширины колонок в экспорте

`recog._auto_fit_columns` подгоняет ширину колонок под содержимое (заголовок +
данные, числа с учётом формата `#,##0.00`, формулы вроде `Ц/ед` и `=SUM(...)` не
учитываются). Фиксированными остаются только «Название позиции» и «Предложено»
(длинный текст переносится по строкам). Верхний предел ширины — 60.


открывается как сессия, иначе распознаётся как прайс-лист.

## Python sidecar

**Файл**: `sidecar.py` в корне репозитория (обёртка над `recog.py` / `normalizer.py`).

```bash
# Распознавание файла (--legal-forms: пользовательский список юрформ)
python sidecar.py --action=recognize --file=/abs/path/to/file.pdf \
    --legal-forms=/path/to/legal-forms.json
# stdout:
{
  "status": "ok",
  "supplierName": "ООО «Ромашка»",   // из текста счёта, fallback — имя файла
  "sourceFileName": "file.pdf",
  "inn": "7707083893",               // с проверкой контрольной цифры, иначе null
  "kpp": "770701001",
  "ogrn": "1027700132195",
  "offers": [
    {"itemName": "Болт М8×40", "qty": 100, "unit": "шт",
     "sumWithVat": 1200.0, "sumWithoutVat": 1000.0}
  ]
}

# Экспорт (AppState передаётся через stdin)
python sidecar.py --action=export --output=/abs/path/to/out.xlsx < state.json
# stdout: {"status": "ok", "path": "/abs/path/to/out.xlsx"}

# Импорт своего xlsx
python sidecar.py --action=import --file=/abs/path/to/saved.xlsx
# stdout: {"status": "ok", "requestName": "…", "suppliers": [...]}
```

Поддерживаемые форматы при recognize: `.pdf`, `.xlsx`, `.xls`, `.docx`.

**Извлечение реквизитов** (`supplier_extract.py`): текст счёта (PDF —
`playa`, уже в зависимостях; docx — параграфы и таблицы; xlsx — все ячейки)
сканируется на организационно-правовую форму; название = краткая форма +
название в кавычках (первое вхождение, «лишнее» после названия отрезается).
ИНН проверяется контрольной цифрой (10/12 знаков), КПП ищется по метке,
ОГРН — по контрольной цифре. Сбой извлечения не валит распознавание позиций.

**Экспорт цен.** В offer из state JSON читаются `priceDriver`
(`"sum"`/`"price"`), `priceWithVat`, `priceWithoutVat`. При `driver=price`
цена пишется значением, а сумма — формулой `=IFERROR(цена*кол-во,"")`;
при `driver=sum` цена — формула `=IFERROR(сумма/кол-во,"")`, как раньше.

**Раскладка книги (recog.build_comparison_xlsx)** — вычисляется заранее,
вставки строк и компенсации merge не нужны:

| Строка | Фикс. часть | Блок поставщика |
|---|---|---|
| 1 | «Заявка: …» | название + «(n/z)» покрытие |
| 2 | «ИНН поставщика:» | ИНН (видимая, копируемая) |
| 3 | скрытая | файлы-источники через «;» |
| 4 | заголовки (№, Название, Кол-во, Ед.изм) | заголовки блока |
| 5.. | группы позиций (merge по вертикали) | предложения; одиночное — merge |
| … | | зона без привязки |
| мета | метки | значения |
| итог | «Сумма» | `=SUM(...)` строкой ниже |
| +варианты | label в кол. 2 | `=SUM(...)` в merge 3..4 |

Всегда второй лист **«Суммы»** — копия «Заявки» со скрытыми колонками блоков,
кроме колонки суммы.

**Импорт** читает группы по вертикальным merge в колонке «Название позиции»,
восстанавливает `linkedRequestItemId` (id генерируются при чтении по порядку
групп), ИНН из строки 2, список файлов из скрытой строки 3; цена-водитель
определяется по тому, значение или формула в колонке «Ц/ед» (книга читается
дважды: `data_only=True` для значений формул, `False` для формул/merge).

Ошибки: всегда `{"status": "error", "message": "…"}` в stdout, код выхода 1.
Импорт не своего xlsx: `{"status": "foreign"}`.

## Автосохранение и сессии

- Сессия хранится в JSON-файле `session.json` в app-support каталоге
  (`getApplicationSupportDirectory()`): `~/.local/share/konkurent_app/` (Linux),
  `%APPDATA%\konkurent_app\` (Windows).
- **Сессия сохраняется только при несохранённых изменениях.** «Чистым» состояние
  делают: успешный экспорт в xlsx, открытие своего xlsx и «Новая сессия»; тогда
  `session.json` удаляется. Пустое состояние тоже «чистое».
  Грязность определяется сравнением JSON-сигнатуры с базовой
  (`cleanSignatureProvider`/`isDirtyProvider`, `lib/providers/session_provider.dart`).
- При изменении «грязного» состояния — debounced write (500 мс). При закрытии
  окна `AppLifecycleListener` сохраняет грязное состояние или удаляет чистое.
- При старте восстанавливается `session.json` (несохранённые изменения); базовая
  сигнатура не задаётся, поэтому они продолжают сохраняться.
- Кнопка **«Новая сессия»** в шапке очищает таблицу; если есть несохранённые
  изменения — с подтверждением.
- `StorageService` — абстракция: `FileStorageService` (прод) и
  `InMemoryStorageService` (тесты).

## Тестирование (для агентной разработки без человека)

Unit-тесты (`test/`):
- `models_test.dart` — сериализация, вычисляемые поля (`pricePerUnit`, `total`, `maxRows`)
- `app_state_provider_test.dart` — add/remove/reorder/sort поставщиков и предложений
- `format_test.dart` — формат и парсинг чисел
- `request_items_parse_test.dart` — разбор вставленного списка (запятая, таб, пустые строки)
- `zoom_provider_test.dart` — масштаб: шаг, границы, сброс
- `session_provider_test.dart` — «грязность» сессии и пометка «сохранено»
- `sidecar_roundtrip_test.dart` — реальный `sidecar.py`: export → import, recognize
  xlsx-прайса, определение чужого xlsx, геометрия книги при 9 позициях заявки
  (пропускается, если нет `.venv`/`sidecar.py`)

Integration-тесты (`integration_test/app_test.dart`), запуск `-d linux`:
- smoke — таблица рендерится, панель инструментов на месте
- редактирование ячейки предложения и позиции заявки
- автоматический пересчёт `Ц/ед`
- сортировка блоков по сумме
- добавление поставщика кнопкой
- создание блока из распознанного файла
- drag-перестановка предложений внутри блока и блоков по горизонтали (вверх и вниз)
- сброс предложения на пустую строку оставляет пробел
- вставка списка позиций заявки через Ctrl+V и кнопкой, и в «Предложено»
- создание предложения вводом в пустую (запасную) строку
- кнопки масштаба меняют zoom
- «Новая сессия» очищает таблицу (с подтверждением при несохранённых изменениях)

Тесты используют `FakeFileEngine` и `InMemoryStorageService` (без Python и ФС).

Ключевой нюанс drag&drop: вложенные `DragTarget` имеют **разные типы**
(`SupplierDrag` / `OfferDrag`, см. `drag_types.dart`). Если оба будут `String`,
внешний target перехватит перетаскивание предложения и перестановка строк
молча не сработает.

## Ограничения

- **Ghostscript** нужен для PDF (lattice-режим camelot). Пользователь
  устанавливает вручную. Sidecar не фейлит заранее (stream-режим работает и без
  Ghostscript), но если распознавание PDF не удалось, а `gs` / `gswin64c` не
  найдены в PATH, к ошибке добавляется подсказка установить Ghostscript. В CI
  ставится через `apt-get` / `choco` (см. `build.yml`).
- **DOCX** распознаётся в `sidecar.py` (`python-docx` из `requirements.txt`);
  без пакета sidecar возвращает понятную ошибку.
- **Версионирование формата** экспортируемого xlsx не реализовано: при изменении
  `config.json` старые файлы могут не открыться.
- **Техдолг (автовысота строк)**: последний перенос строки в редких случаях
  не помещается — например, «Шпилька резьбовая М 12х2000 DIN 975 цинк»
  обрезается по последнему слову. Замер `TextPainter`'ом эпизодически
  расходится с реальным переносом (округления `TextScaler`/ширины `Expanded`).
  Подробности и направление фикса — в `AGENTS.md`, гоча про
  `rowHeightsProvider`.
